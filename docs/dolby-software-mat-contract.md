- ms12v2_matenc_process at 0x1cedc0 calls mat_enc_emdf_payload_set at 0x1cf0dc when metadata length is positive; then mat_enc_pcm_add_bytes at 0x1cf0ec and mat_enc_process_chunk at 0x1cf14e. - A lower-level exported mat_enc_mlp_add_bytes (0x31cf94) sets input mode 1 at 0x31cfc2 when unset, accounts available buffer space against 0xeff0 bytes, conditionally copies input and reports accepted / pending bytes at 0x31d058–0x31d05c. Partial consumption is supported. mat_enc_process_chunk (0x31d7c8) dispatches mode 1 at 0x31d800 to mat_enc_dthd_process_au (0x31d81e), mode 2 to mat_enc_pcm_process_chunk (0x31d858). This is a codec-aware compressed packaging implementation, distinct from the PCM wrapper. No actual output bytes verified or assumptions of bit-perfect metadata retention. No PLT relocation for mat_enc_mlp_add_bytes or ms12v2_matenc_process found in this library; absence is not exhaustive call-graph proof.

## Decision and outstanding work

This is a meaningful alternative to blind handcrafted MAT framing: the stock software library includes an existing codec-aware raw MLP/TrueHD-to-MAT packer. But the previously tested packed MAT was not recognized on MM ingress; producing a valid software MAT stream alone cannot establish its path to eARC. Do not call proprietary functions with guessed ABI, modify status/entitlements, or inject encoded bytes into PCM. Prioritize checking whether an already supported integration loads these functions, and mapping the actual MM decoder framing contract; the fallback is a licensed/supported offline reference comparison and explicit output transport integration, not a claimed app-ready implementation. No new TV test, root, firmware edits or binary redistribution. Existing exact same-sample HDMI control remains deferred.
