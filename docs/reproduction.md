# Reproduction guide

## Prerequisites and setup

Android TV 12+ (API 31); the original target is Android 14. JDK 17, SDK 34 / build-tools 34.0.0, adb, Python 3.9+, FFmpeg and FFprobe. Select the physical TV using `adb devices -l` and `$env:ANDROID_SERIAL = '<connected-device-serial>'` (wireless pairing port is not the debug connection port). Do not publish the serial or local network addresses. Keep the local `out/debug.keystore` across updates; different signing keys require uninstall/reinstall, which removes app data.

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
python .\tools\prepare_samples.py 'C:\media\amaze.m2ts' --eac3 'C:\media\joc.mkv'
powershell -ExecutionPolicy Bypass -File .\install_samples.ps1
powershell -ExecutionPolicy Bypass -File .\install_tunnel.ps1
```

Omit `--eac3` if no suitable source. Explicitly select the correct stream with `--truehd-index` / `--eac3-index` when multiple audio tracks exist. Generated samples are copied, not TrueHD re-encoded. The synthetic PCM/video fixtures can be regenerated by `python tools/generate_tunnel_samples.py` (not byte-identical to the archived original video). Inspect original sample with `ffprobe`. Confirm the source on a known-good external HDMI path. For native-player comparisons, `scripts/native_test.ps1` muxes the same video and raw audio with stream copy.

Alternative build: `gradle assembleDebug` (Gradle 8.7, AGP 8.5.2) or Android Studio. APK is `app/build/outputs/apk/debug/app-debug.apk`. The GitHub workflow builds using the Gradle route. The local packaging scripts use the direct SDK/JDK route. APK binaries are not included.

## Test protocol

1. Close other media apps. Set eARC on and select Pass Through on the TV. Verify soundbar is on eARC. Keep volume very low, stop immediately for unexpected noise. Avoid changing mode during a test.
2. Start application, inspect capabilities. Record PCM stereo, EAC3/JOC (if present), TrueHD RAW, explicit offload and HW AV sync results; use Open only before trying direct IEC/MAT modes. See original-v0.1.0.md. Missing file is not codec failure.
3. Repeat the same test in Auto, recording selected setting. Use soundbar Info to identify displayed input codec; distinguish original Atmos from Dolby Surround upmix.
4. Full A/V tunnel: Inspect, PCM 5.1 control, both TrueHD initialization orders, 16-AU and 24-AU grouped writes. The PCM test uses quiet clean sine tones. Record observed audio/video for each. Optional EAC3/JOC tests only with verified suitable media.
5. Run live logcat in a separate PowerShell **before playback** (ring buffer may rotate):

```powershell
New-Item -ItemType Directory -Force .\private\reports | Out-Null
adb logcat -b all -v threadtime -T 1 > .\private\reports\live.log
```

Stop with Ctrl+C after recording all observations. While a specific audio-only or tunnel test is active, run `collect.ps1 -Name test` or `collect_tunnel.ps1 -Name group16_bypass`; heavy dumps may finish after the test, so check timestamps and active tracks. Pull final logs with `scripts/collect_final.ps1`. These scripts never clear log buffers. Review raw reports locally; they can disclose device identifiers, app names, URLs and network addresses.

## Firmware inventory and static analysis

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\collect_firmware.ps1
python .\tools\scan_firmware.py .\private\firmware_libs --out .\private\native-analysis
python .\tools\analyze_logs.py .\private\reports --out .\private\log-analysis.json
```

Commands only gather read-accessible files. `lshal`, `/proc/<pid>/maps`, `/proc/asound` and `tinymix` can fail due to permissions or missing tools; record the failure, do not change privileges. If the TV has been restarted, update the optional process IDs based on `ps -A` rather than assuming old PIDs. The inventory script extracts original candidates across all three stages, not the entire firmware. Firmware hashes and symbol addresses are version-specific. Do not publish `.so` files.

## Interpret results properly

- `isDirectPlaybackSupported`, actual track creation, Java offload flag and HAL output flag are distinct checks.
- `AudioTrack.write` bytes accepted do not prove a decoder recognized them; inspect DSP counters, playback position and audible result.
- Video callbacks demonstrate video progress, not correctness of encoded audio. Compare audio/video clocks with startup latency in mind.
- Atmos indication from the soundbar is not a wire capture. For high-confidence conclusions compare the same input bytes via a known-good HDMI path.
- Logs ending after a track closes may show the fallback PCM mixer rather than the test route.
